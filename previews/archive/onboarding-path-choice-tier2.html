Path choice — Tier 2 mock

Copy and structure only. Three panels per card collapse to one discriminator line plus steps; the detail moves behind a disclosure; the card title leads with your situation rather than the product name. Word counts on each card are measured live from the DOM (collapsed disclosure content excluded), not asserted.

Mobile fold test

real 375 × 812 frames — everything below the dashed line needs a scroll

The test Tier 2 has to pass. Today card 1 is 552px tall and card 2 starts at y=745, so 67px of the second option peeks above an 812px fold — the page reads as one option, not a choice.

Collapsing one panel isn't enough. Variant A's desktop card still runs ~350px on a phone, which pushes card 2 about 75px past the fold. So below sm the numbered steps join the disclosure too: the mobile card is title + one discriminator line + "How it works" + button. Both options then land whole, with ~160px to spare. This is the one place the mock diverges by viewport, and it's the change that actually makes the choice legible on a phone.

What this changes in the component

src/components/recipient/RecipientStepPathChoice.tsx
  • The card stops being one giant <button>. A disclosure toggle can't nest inside a button — invalid HTML, and the click targets would fight. The card becomes a <div> with a real <button> CTA. That also fixes the 440-character accessible name each card currently announces as a single control, and lets the app's blue focus ring apply instead of the browser's default gray outline.
  • Grid tracks follow the visible card count — 2 cards cap at ~812px, 3 cards at ~1148px. No dead column in either state.
  • The numbered steps sit inside the disclosure below sm, outside it above. One <details> whose <summary> and contents change at the breakpoint — it's what gets both options above the mobile fold.
  • The three cards collapse into one <PathCard> + a config array. The markup is currently repeated three times, which is how the padding hacks (pr-14 vs pr-20) drifted apart. ~237 lines → ~120.
  • The "You pay" badge renders only when a "Buyer pays" card is also on screen — it's a differentiator, so it should appear only when there's something to differentiate from.
  • Hardcoded violet-*/blue-* move to per-card CSS variables, the way this mock does it. Dark mode isn't shipped today, so this is consistency work, not a live bug fix.
